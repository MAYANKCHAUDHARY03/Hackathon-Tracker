### Per-phase spec (carry these rules into the relevant phase's implementation)

- **Phase 28 (Knowledge Graph):** model relationships (`solves`, `uses`, `belongs_to`, `created_by`, `participated_in`, `evaluated_by`, `mentored_by`, `evolved_from`, `inspired_by`, `deployed_at`). Every inferred edge must carry a provenance tag: `verified | user-provided | imported | AI-inferred`.
- **Phase 29 (Semantic Search):** combine keyword + semantic + structured filters + graph + permissions. Every result must return a **match reason** (which criteria matched, not just a score).
- **Phase 30 (Challenge Exchange):** discovery layer, not a transaction marketplace. Flow: Organization → Problem → Challenge → Hackathon/Program → Teams → Solutions.
- **Phase 31 (Research Bridge):** link projects to papers, patents, datasets, repos, institutions. Source provenance stays visible even when AI summarizes relationships.
- **Phase 32 (Open API):** versioned `/api/v1/...`, OAuth apps, API keys, rate limits, scopes, webhooks, usage analytics, developer docs — all inside the existing multi-tenant authorization model.
- **Phase 33 (Data Exchange):** versioned schemas (`InnovationSchema v1`, `v2`, …), JSON/CSV/NDJSON export/import.
- **Phase 34 (Trust & Verification):** every achievement needs status, verifier, source, date. **AI alone can never mark something verified.**
- **Phase 35 (Innovation Passport):** portable, user-controlled-visibility profile (identity, skills, projects, hackathons, awards, contributions, verified achievements, team experience, impact).
- **Phase 36 (Org Intelligence):** dashboards backed entirely by real data — no placeholder metrics shipped as if real.
- **Phase 37 (AI Copilot):** must follow `User → Intent Detection → Permission Check → Knowledge Graph/Search → Verified Data → AI Reasoning → Answer + Evidence`. Every answer returns Evidence, Source Entities, Confidence, Recommended Action. AI queries trusted platform data — it does not invent knowledge.
- **Phase 38 (Forecasting):** all outputs explicitly labeled as predictions. No forecast may auto-trigger a high-impact action.
- **Phase 39 (Impact Measurement):** track the full funnel (Participation → Projects → Prototypes → Pilots → Deployments → Startups → Jobs → Impact) and support org-defined custom metrics.
- **Phase 40 (Observatory):** aggregate only permissioned data; privacy/aggregation controls are mandatory, not optional.
- **Phase 41 (Federation):** enable shared programs/challenges/mentors/judges/discovery across orgs — tenant isolation stays absolute.
- **Phase 42 (Developer Ecosystem):** portal, docs, SDKs, webhooks, OAuth apps, sandbox, API explorer, extension marketplace, versioning compatibility.
- **Phase 43 (Global Scale):** stop here and get explicit human sign-off before building. Do not implement for its own sake.
- **Phase 44 (Governance):** data residency, retention, privacy, consent, auditability, security policy, org-level AI policy, export, account deletion, incident transparency, admin controls.
- **Phase 45 (Innovation Network 1.0):** final integration milestone — Participants / Organizations / Knowledge all resolve through the Knowledge Graph into Discovery, Matching, and AI, driving the Prototype → Pilot → Startup → Impact lifecycle.

## 5. Auto-continuation rule

For each phase:

1. Implement the phase fully (schema/migrations, backend, frontend where applicable, tests, docs).
2. Run the test suite and lint/typecheck; fix failures before proceeding.
3. Write a short completion note in `/docs/phases/phase-<N>.md`: what shipped, what was deferred, any deviations from spec and why.
4. Commit the work on a phase branch (`phase-28-knowledge-graph`, etc.) with a clear commit message.
5. **Immediately begin the next phase in the queue** — do not stop to ask "should I continue?" or wait for approval between phases.

**Exceptions where you must stop and ask a human, even mid-sequence:**
- Before starting Phase 43 (Global Scale Architecture) — demand must be confirmed first
- If a phase requires a decision that would change the core data model in a way not already specified above
- If tests reveal a security or tenant-isolation issue that the spec doesn't clearly resolve
- If you hit an external dependency (paid service, org policy, legal/privacy question) you can't resolve yourself

Otherwise: complete a phase → log it → move to the next. Keep going through Phase 42, then pause for the Phase 43 checkpoint, then resume Phase 44–45 on approval.

## 6. Definition of done (applies to every phase)

A phase is not "done" until:
- [ ] Code builds and passes lint/typecheck
- [ ] Automated tests cover the new behavior
- [ ] Multi-tenant authorization has been checked against the new surface area (API, data, or UI)
- [ ] Any AI-generated relationship/answer/prediction carries the required provenance/confidence/labeling per §4
- [ ] A short phase doc exists in `/docs/phases/`
- [ ] Work is committed on its own branch
